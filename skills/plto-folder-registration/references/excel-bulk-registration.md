# 플토 엑셀 일괄등록: 검증된 입력·첨부·재시도

2026-11-04 사례 상품 B 작업에서 일반 30건, 단일 13건, 토스 수정 1건의 실제 엑셀 등록을 확인했다. 아래 절차는 당시 확인된 UI와 파일 형식에 대한 지침이다. 상품별 카테고리·옵션·가격·계정은 현재 자료로 다시 확인한다. 상품번호, 작업번호, 기기 경로는 로컬 receipt에 둔다.

## 업로드 전 점검

1. 일반/단일 공식 양식을 구분하고 현재 열 이름, 항목명 행, 필수값을 확인한다. 당시 공식 양식은 일반 v23, 단일 v29, 항목명 1행이었다. 버전은 고정하지 않는다.
2. 쿠팡·토스는 **대상 계정에 매핑된 카테고리**와 필수 옵션명을 확인한다. 같은 마켓의 다른 계정 매핑이 있다는 것만으로 대상 계정도 준비됐다고 판단하지 않는다.
3. 아래의 정확한 옵션명과 Excel 호환 저장을 확인한 파일을 첨부한다. 원본 계산기·상품 자료 대신 생성한 업로드 사본만 수정한다. 기존 이미지 호스팅 URL은 재사용한다.
4. 이전 작업에서 성공한 행·마켓을 제외한다. 부분 성공 후 원본 전체 파일을 다시 올리지 않는다.

## 파일 선택이 열리지 않을 때

파일 선택기 시간초과와 첨부 후 Excel 읽기 오류를 구분한다. 현재 도구의 업로드·문제해결 문서를 먼저 읽고 지원 API만 사용한다.

- 클릭이 실패한 동일 입력을 계속 클릭하지 않는다. 미저장 내용을 보존하고, 선택된 Chrome 연결의 **새 플토 작업 탭**에서 일괄등록 창을 연다. 연결 ID를 바꾸거나 같은 파일 URL 접근 권한을 다시 요구할 필요는 없다.
- 최신 AX/DOM에서 실제 파일 입력을 확인한다. `waitForEvent('filechooser')`를 먼저 시작한 뒤 **파일 입력에 Space**를 보내고 반환된 선택기에 `setFiles(절대경로)`를 사용한다. 당시 클릭으로 열리지 않던 입력에서 이 방법이 성공했다.

```javascript
// tab, fileInputAXId, uploadPath는 현재 관찰/로컬 파일에서 확보한다.
const pendingChooser = tab.playwright.waitForEvent('filechooser', {timeoutMs: 10000});
await tab.pressKey(fileInputAXId, 'space');
const chooser = await pendingChooser;
await chooser.setFiles(uploadPath);
await tab.getAXState(); // 선택된 파일명이 실제로 표시되는지 확인
```

- 파일명이 표시되면 첨부 문제는 해결된 것이다. 이후 실패는 서버 작업 결과의 정확한 오류로 분류한다. 등록 성공으로 바로 기록하지 않는다.
- 이 경로도 실패하면 새 관찰과 도구 진단에 근거해 다른 지원 방법을 선택한다. 같은 시간초과를 반복하거나 Windows URL 검증 차단을 우회하지 않는다. 사용자가 엑셀 일괄등록을 지정했다면 건별 입력으로 조용히 대체하지 않는다.

## `.xlsx`지만 플토가 읽지 못하는 경우

확인된 오류: `Microsoft Excel이 아닌 프로그램에서 생성된 파일은 읽을 수 없습니다. Microsoft Excel에서 열어 Excel 통합 문서(*.xlsx)로 다시 저장한 후 재업로드 해주세요.`

- artifact-tool 생성 파일이 정상적인 XLSX여도 당시 플토 파서는 거부했다. 확장자를 바꾸거나 같은 바이트를 재첨부해 해결하려 하지 않는다.
- 같은 생성 경로를 다시 사용할 때는 **첫 업로드 전에 Microsoft Excel로 업로드 사본을 재저장**한다. 새 생성 경로가 플토에서 이미 검증됐으면 불필요하게 재변환하지 않는다.
- Windows에서 Microsoft Excel이 설치돼 있으면 파일 변환에 Excel COM `Workbooks.Open(input, 0, true)` → `SaveAs(output, 51)`을 사용할 수 있다. `51`은 Excel 통합 문서 XLSX다. 입출력은 서로 다른 **절대 Windows 경로(역슬래시)**로 지정한다. 당시 슬래시 경로 SaveAs는 실패했고 역슬래시 경로는 성공했다.
- 별도 Excel 인스턴스를 만들고 변환한 통합문서와 그 인스턴스만 닫는다. 사용자가 열어둔 Excel을 종료하거나 모든 Excel 프로세스를 정리하지 않는다. 기존 결과를 무조건 덮어쓰지 않는다.
- COM 활성화가 `80070520` 세션 오류로 막히면 동일 명령을 반복하지 않는다. 로컬 파일 변환에 필요한 실행 권한을 도구의 정식 승인 경로로 확보하거나 Excel의 지원 UI로 재저장한다. 권한 검토가 거부한 동작을 우회하지 않는다. 기기별 실행 파일 경로·인증정보를 공유 스킬에 넣지 않는다.
- 변환 전후 모든 시트의 머리글·데이터 셀 값을 읽기 전용으로 비교한다. 특히 바코드 문자열, 줄바꿈 옵션, 가격, HTML/이미지 URL이 보존돼야 한다. 값이 달라지면 업로드하지 않는다. 검토용 파일이나 원본 계산기를 업로드 파일로 오인하지 않는다.

## 쿠팡·토스 옵션명은 같은 것으로 취급하지 않는다

당시 기타다이어트식품 카테고리에서 확인한 **선택 후 옵션명 입력칸의 실제 문자열**:

| 마켓 | 필수 수량 | 정수 옵션의 정확한 이름 | 엑셀 옵션 첫 줄 예시 |
|---|---|---|---|
| 쿠팡 | `수량` | `개당 캡슐/정` | `[수량=개당 캡슐/정]` |
| 토스 | `수량` | `(택1) 개당 캡슐/정` | `[수량=(택1) 개당 캡슐/정]` |

다음 줄의 예시는 `1개=60정`, `2개=60정`이다. 옵션 수량·포장 정수는 실제 상품 자료를 사용한다. 60정이나 1~6개를 다른 상품에 고정 적용하지 않는다.

- 토스에서 `(택1)`을 빼고 쿠팡 문자열을 그대로 썼을 때 `필수 추천 옵션을 모두 선택해주세요`로 실패했다. 해당 토스 행의 정확한 옵션명만 수정한 엑셀은 1건 성공했다.
- `(택1)`을 모든 마켓에 붙이거나 일괄 삭제하지 않는다. 다른 카테고리는 옵션명·공백·단위·필수 조합이 다를 수 있다. 공식 지원 옵션표 또는 UI에서 옵션을 실제 선택한 뒤 입력칸 값까지 확인한다. 팝업 버튼의 안내 문구만 보고 문자열을 추측하지 않는다.
- 카테고리 변경은 옵션을 초기화할 수 있다. 최종 카테고리에서 옵션 수, 값/단위, 추가금액, 재고, 단위가격을 다시 대조한다.
- 토스 판매자센터의 숫자 옵션 입력은 당시 쉼표 목록을 분리하지 않고 `1,2,3`을 `123`으로 처리했다. 개별 값을 하나씩 추가하고 생성된 옵션을 확인한다. 미저장 초안 정정과 저장된 옵션 삭제를 구분한다.

## 일부 행만 실패한 경우

- 작업관리에서 작업번호·성공/실패 건수·실패 결과를 확인한다. 전체 14행 중 토스 1행만 실패했다면 **수정된 토스 1행만** 올린다.
- 이미 존재하는 판매자관리코드에 신규 업로드가 충돌하는 경우 새 실패 전용 코드로 그 행만 생성하고, `판매자관리코드 선택 수정 → 기존 마스터 코드 → 중복확인`으로 원하는 마스터에 합친다. 동일 계정의 기존 상품 유무와 이동 안내를 먼저 확인한다. 성공 상품 삭제/재생성으로 해결하지 않는다.
- 일반/단일 양식 때문에 마스터가 나뉘면 동일 수량의 마스터에 연결한다. 최종 마스터 수와 계정별 레코드 수를 검증한다. 쿠팡·토스 옵션상품은 수량별로 복제하지 않는다.

## 전송 후 토스 추가 확인

- 플토 공통 시중가로 전송하면 당시 토스 옵션 정상가는 `공통 정상가 + 옵션 추가금액`이 됐다. 판매가 구간이 달라지는 묶음은 승인된 시중가 가산 규칙과 차이가 날 수 있다.
- 판매자센터에서 옵션별 판매가/정상가를 비교하고 승인된 값으로 필요한 정상가만 수정한다. 사례 상품 B는 4/5/6개 정상가를 69,100 / 84,500 / 100,000원으로 저장 후 재조회했다. 이는 검증 예시이며 다음 상품의 가격표가 아니다.
- 마켓 직접 보완한 카테고리·옵션 정상가와 플토 값의 차이를 receipt에 기록한다. 다음 전체 수정 전송 전에 차이를 해결하거나 지원되는 필요한 항목만 전송하여 보완값이 되돌아가지 않게 한다.
- 플토 전송 성공이어도 판매자센터에서 반려될 수 있다. 토스 `카테고리 불일치`는 해당 상품의 근거와 허용 카테고리를 대조해 보완한다. 사례 상품 B에서 식물추출물 분류로 수정 접수했으나 당시 최종 승인은 확인되지 않았다. 이 분류를 모든 상품의 정답으로 저장하지 않는다.
- `전송 성공`, `기존 반려`, `보완 후 검수중`, `판매중`을 각각 기록한다. 재검수 접수로 판매 완료를 선언하지 않는다. 브랜드 신규 등록·문의 제외와 성공 마켓 중복 전송 금지는 유지한다.
