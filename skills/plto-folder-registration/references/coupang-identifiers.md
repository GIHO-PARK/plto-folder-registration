# 쿠팡 바코드·MPN 전송 오류 조사

2026-11-04 사용자 기준 및 UI 확인 반영. 정책이나 API 필드가 달라졌을 수 있으면 아래 공식 문서를 다시 확인한다. 브랜드 등록·바코드 조회 정상·쿠팡 상품 등록 성공은 서로 다른 결과다.

## 현재 사용자 입력 방식

소싱계산기 `02.마진계산기`의 **AB열에 바코드가 있으면 입력하고, 비어 있으면 공란으로 등록을 진행한다**. 해당 상품명·규격·수량과 같은 행인지 확인한다. 같은 열의 앞뒤 상품 번호를 대신 쓰지 않는다. 최신 원본에도 비어 있다면 번호만 없다는 이유로 다시 요청하거나 선제 보류하지 않는다.

값이 있는 동일 제품의 수량 옵션은 1개 옵션에만 원본 GTIN을 입력하고, 나머지 옵션의 바코드란은 비운다. 기본정보 맨 아래 바코드란에도 같은 값을 입력한다. 사용자 지시 없이 모든 옵션에 복사하거나 옵션을 삭제하지 않는다. 번호는 문자열로 보존하며 잘못된 형식/다른 상품과의 불일치가 확인되면 임의 보정하지 않는다.

사례 상품 A과 기존 사례 상품 E는 바코드 공란으로 쿠팡 판매중인 사례를 UI에서 확인했다. 이는 모든 상품/카테고리의 바코드 면제나 `emptyBarcode` 전송을 입증하지 않는다. 실제 필수 식별정보 오류가 발생하면 해당 상품·마켓만 보류하고 다른 마켓은 계속 진행한다.

사례 상품 D에서는 이 구성을 저장한 뒤에도 `MPN/GTIN 속성이 누락되었거나 유효하지 않습니다. 상품 옵션 속성을 확인해 주세요.` 오류가 지속했다. 모든 옵션에 같은 바코드를 넣었을 때는 중복 오류가 났다. 이것만으로 별도 묶음 GTIN이 필수이거나 플토 결함이 확정됐다고 판단하지 않는다.

## 확인된 정책과 표기

- 쿠팡 공식 FAQ: 옵션의 구성은 동일하고 수량만 다르면 같은 바코드를 사용할 수 있다. 동일 등록상품ID의 옵션으로 구성해야 한다. 서로 다른 규격·구성에도 무조건 같은 GTIN을 쓸 수 있다는 뜻은 아니다.
- `70 MLT`와 `70ml`는 같은 용량이다. 용량을 kg 중량란에 복사하지 않는다. 배송 무게·제품 순용량·2개 묶음 총용량을 구분한다.
- GTIN-13을 14자리로 표시할 때 붙인 선행 0은 다른 상품 번호를 의미하지 않는다. 예: `원본 13자리`와 `0 + 원본 13자리`. 원본 식별번호는 문자열로 보존하고 지수 표기에서 누락된 숫자를 추측하지 않는다.
- 조회 결과의 제조/유통사에는 유통사가 표시될 수 있다. 고시의 제조업자와 책임판매업자를 각각 대조한다. 이름 차이만으로 오류라고 단정하거나 실제 제조업자를 유통사 이름으로 바꾸지 않는다.
- 공식 MPN은 제조사/브랜드가 부여한 품번이다. 상품명, 수량 옵션명, 내부 SKU를 만들어 MPN으로 입력하지 않는다.

## 조사 순서와 한계

1. 기존 플토 코드, 실제 계정, 상품 저장 여부, 작업번호·시각·오류 원문을 확인한다. 이미 등록된 쿠팡 상품이 있는지도 조회해 중복 신규 등록을 피한다.
2. 원본 GTIN과 현재 1개/나머지 옵션/기본정보 바코드 값을 확인한다. 수량, 개당 용량, 브랜드와 공식 MPN 여부도 함께 기록한다. 사용자 수정 중인 화면은 저장값과 구분한다.
3. 템플릿에 바코드 등록/전송 설정이 있는지 조회한다. EMP 도움말의 메뉴가 플토2.0에도 있다고 가정하지 않는다. 공용 템플릿은 조사 목적으로 덮어쓰지 않는다.
4. 쿠팡 개발자 FAQ는 기존 `barcode`, `modelNo`, `emptyBarcode`와 `attributes`의 `Global Trade Item Number` / `Manufacturer Part Number`를 구분한다. 따라서 바코드 조회가 정상이어도 식별 속성이 정상 전송됐다는 증거는 아니다. 실제 전송 자료가 허용된 UI/공식 도구로 보이면 `items`별 식별 속성, `brandId`, 누락·중복 위치와 상세 오류를 확인한다. 인증정보를 추출하거나 숨은 내부 API로 조회하지 않는다.
5. 전송 데이터가 보이지 않으면 플토의 전달 방식 문제를 원인 후보로 제시하되 확정하지 않는다. 지원 문의가 필요하면 작업번호와 확인할 필드가 포함된 문안을 준비하고, 사용자가 보내라고 지시했을 때만 전송한다.
6. 재전송은 근거 있는 수정 또는 사용자의 명시적 재시도 요청이 있을 때만 해당 실패 상품에 수행한다. 동일 오류가 반복되면 중단하고 기존 옵션·정확한 상품 정보와 재개 지점을 보존한다. 미확인 해결책은 성공한 자동화 규칙으로 승격하지 않는다.
